# 内置四视图预处理

此模块随模型 skill 一起分发，包含生成约束、验收、交接格式和母版，不读取独立 chibi-character-sheet。维护时与独立出图 skill 的对应规则和资产同步检查；本入口只负责预处理，不递归调用建模。

1. 查看原始图片与 [固定母版](assets/style-master.png)。用户指定母版优先，否则使用随附灵梦图，仅继承身体、头脸、表情、姿势、相机、布局和渲染，不继承灵梦服装配色。[换装示例](assets/outfit-example.png) 仅作裁片材质参考，不成为第二比例母版。[配置与来源](assets/profile.json) 记录资产哈希。
2. 提取角色身份、发型分组、服装裁片、配饰挂点和鞋袜，未知背面标记推定。保留上游精修动态/静态/性能要求供后续建模使用。
3. 读取 [分阶段生成约束](generation.md)。原始插画先 Stage 1 三维 Q 版概念翻译，再 Stage 2 固定母版换装；已有适合概念图可跳过 Stage 1，记录理由。合格四视图直接复用，不额外生成。
4. 使用当前可用的内置 image_gen 工具，遵循实际工具 schema；可用时读取 imagegen 技能的相关工具指引。每次明确输入角色：原始参考、概念来源、母版编辑底图。先查看本地图片，不能仅传文件名假装已理解；不虚构参数，不用程序画占位图替代图像生成，不自动改用付费 API。当前无图像工具时返回主流程报告缺项。
5. 按阶段分别组装提示词，不把两套约束混发。Stage 1 允许合理设计解释；Stage 2 固定头脸、体型、姿势及四列相机。表面图案、大型发束、衣物厚度等细则见生成约束。两阶段均只生成完整单行四视图，不拆件、不增加角色。
6. 保存原图副本、母版、版本化阶段图和实际提示词到角色 design 目录。用真实图像执行 [视觉验收](acceptance.md)，每阶段最多两轮针对性修订；仍未通过则返回 needs_revision 和具体失败项，不伪造通过结果。
7. 按 [交接格式](handoff.md) 写 design-handoff.json，记录实际路径/哈希、身份锚点、连接关系、推定和视觉评审。返回当前建模流程重新确认并继续，不能把设定图当模型渲染或动态验证证据。

用户要求仅预检时不进入生成；明确禁止生图时按其选择处理。未知角色身份不能靠生成图猜出。四视图可提高设计清晰度，但不能保证二维未知结构的真实性，也不能保证与母版逐像素一致。

此处二维四视图母版只用于图像预处理与布局；三维建模以 本包 assets/baseline 银灰狼耳少女基准为准，不把二维旧角色当作第二个三维基准。
