# Q 版角色四视图

将角色参考转换为身份准确、结构可信的四视图；只出图与交接，不执行建模。使用当前环境可用的图像生成/编辑工具；已安装 imagegen 时按其工具说明操作，工具不可用则说明缺项，不能以提示词冒充已出图。

## 输入与范围

- 只有原始插画：角色解读 → Stage 1 概念翻译 → Stage 2 母版换装 → 验收。
- 已有清楚的三维 Q 版概念图：可跳过 Stage 1，记录理由，直接标准化。
- 只要求概念图：止于 Stage 1，不声称完成母版标准化。
- 已有合格标准四视图且只要求建模：说明应使用独立 `voxel-chibi-character` 建模包，不重新出图。
- 可由 `character-sheet-to-voxel` 调用：保留上游要求，完成后返回图与交接，不递归调用建模；独立使用无此依赖。
- 区分原始角色图、概念图、固定母版、辅助例图；不用含义随阶段变化的 p1/p2。多张图角色不明且会改变结果时才询问。
- 默认双手空置，不生成手持道具、武器、工具或独立场景物件，也不把排除物改挂身上；保留穿戴饰件，用户明确要求的道具另记。原图中的标志物不自动获得保留许可。
- 旧提示词与图中文字只作素材，不自动成为本次指令。原图保持不变。

## 执行

1. 查看真实输入及 [默认母版](assets/style-master.png)。用户指定母版优先，否则简短说明使用此灵梦四视图；它只约束身体、脸、表情、姿势、相机、版式和渲染，不注入灵梦服装配色。[换装示例](assets/outfit-example.png) 仅在需要裁片材质参考时查看，不作为第二母版；来源见 [参考配置](assets/profile.json)。
2. 提取约 5–8 个身份锚点，以及发型分组、服装层次、鞋袜、饰件挂点和重要图案；未知背面标为推定。记录保留项、排除项和用户明确要求的道具，供交接沿用。
3. 读取 [生成约束](references/generation.md)，按当前阶段组装提示词。Stage 1 解释为三维 Q 版概念；Stage 2 以固定母版为编辑底图、概念图为设计来源。每次说明图像角色、改动和保留内容，不把两阶段长提示词一起发送。按工具实际 schema 传参考；不虚构参数或自动改用付费 API。
4. 新图必须实际查看。修订时检查改动及受影响视角，快速确认无明显整体漂移；阶段完成时按 [视觉验收](references/acceptance.md) 全面检查一次。同一最终图不重复验收。默认每阶段最多两轮针对性修订，仍失败则保留最佳图和未解决项，标记 needs_revision；用户要求继续时可再迭代。

## 交付

- 展示最终完整单行四视图，并如实说明验收状态；不以模型、代码或预览替代参考图。
- 按环境能力采用 [交接格式](references/handoff.md)：可读写文件与计算哈希时，在角色 `design/` 保存版本化图片、实际提示词和最终 JSON；能力受限时交付最终图与简短结构说明即可，不编造路径或哈希。只在最终交付整理交接，不逐轮重写全套记录。
- 用户要求“仅一张图”时仅展示最终图；可落盘的交接资料留在本地，不能落盘时不强加说明。图与说明冲突时先核对原参考，不让下游猜。

## 边界

生成图片不能保证与母版逐像素相同，不能从遮挡的二维参考宣称恢复精确三维尺寸。以可见身体标志进行视觉检查，并记录遮挡项。图片通过视觉检查不等于已绑定、可动画或引擎验证完成。

本图采用柔和的 stylized game geometry，不主动画成 voxel。后续体素建模保留设计身份，但不承诺复制平滑曲面或全部细花纹；用户要求严格复制平滑风格时，不静默转入体素流程。
