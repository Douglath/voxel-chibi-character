# 四视图到带动效像素模型

本 skill 内置四视图预处理，建模执行依赖已安装的 `voxel-chibi-character`。读取相邻 `../voxel-chibi-character/SKILL.md` 及它要求的相关参考。若路径变化，按当前 skill 列表查找；依赖缺失时说明具体缺项，不能把空模板冒充模型，不静默换用付费 3D 服务。

## 输入与范围

- 接收最终单行四视图；有 `design-handoff.json` 时读取并核对引用图、SHA-256、phase/status 和评审。格式见 [内置交接格式](references/sheet/handoff.md)。
- 单独输入现成设定图也可执行：查看图像，自行提取身份锚点、部件关系、配色、未知信息，在新模型工程保存输入和设计记录。不要求用户先运行另一 skill。
- 每次收到图片，先执行下面的输入预检，包括只有一张原图、已有四视图以及上游交接的情况。根据可见证据选择直接建模、先生成/修正四视图或补充关键信息，不默认任何图片都适合建模。
- 输入记录为 needs_revision 或图中有重大连接矛盾时，先解决具体阻断问题；不能默默选择错误列。缺少背面可以做最小推定并记录，重要身份细节无法判断才询问。

## 建模前的输入预检与自动补全

在创建模型工程或 scaffold 前读取 [输入适用性与路由](references/input-readiness.md)，查看真实图片，而不是根据文件名、分辨率或“有四列”判断合格。简短告知判定和具体原因，并记录 inputReview。

默认在建模前准备合格四视图：已有合格四视图则复用；只有原始插画、单视图或不合格多视图时，执行 [内置四视图流程](references/sheet/pipeline.md)。身份信息不足时先补充信息。**不依赖独立 chibi-character-sheet 安装，不要求用户另说“先出图”，也不额外请求确认。**此预处理优先于底层建模 skill 的“不默认生成中间图”；用户明确禁止生图、只要求预检或限制预算时服从用户。

带上原始参考、具体缺陷、身份锚点、母版选择和动态模式，在本 skill 内依次完成设计与建模。预处理结束后重新查看最终图和评审，合格再继续；最多一次自动预处理流程，内部修订按内置规则限制，不再次调用模型入口或独立出图 skill。

内置参考缺失、图像工具不可用或生成失败时，明确实际缺项和影响，提供恢复本 skill 资源、启用图像工具、补充四视图或由用户明确选择按现图继续等恢复方式。无需提示安装独立出图 skill；仅有规则和母版不代表图像生成能力可用。不自动切换收费 API，不默默继续依赖不合格参考。

## 动态模式：自然语言匹配

理解用户语义，不要求使用固定口令。明确说“精致动态的模型”“完整精修动态”“所有可能的地方都加动态”“所有适合的部件都动起来”“最高精细度的附加动态”等，即选择 **完整精修动态模式**，无需让用户再次粘贴详细提示词或确认模式。上游设定图流程中已表达的动态要求也应继承。

- 普通“带动效／动态模型”：默认轻量模式，2–3 类部件、通常 4–8 新骨。
- 明确追求动态精致度或全面覆盖：完整精修模式，读取 [完整精修动态](references/refined-dynamics.md)。此模式取代本流程和底层 skill 的默认部件数量预算，但不取消其连接、绑定、验证与交付规则。
- 仅说“精致模型”或“精致外观”不自动扩大动态范围；结合上下文判断，不因一个孤立形容词提高成本。
- 明确静态/禁用动画、限定部件或给出性能预算时，以这些具体限制优先。完整精修不表示无限骨骼或无视性能；在限制内优先调好响应并记录未覆盖项，不悄悄回退到默认轻量模式。

将所选模式写入 character-spec.json 的 dynamics.mode（lightweight / refined / static）；记录选择原因、选中及省略部件，生成时简短说明即可，不新增许可步骤。

## 兽耳、尾巴与带状附件

输入含这些部件时，读取底层 `voxel-chibi-character` 的 `references/ears-tails-straps.md`（相对本入口为 `../voxel-chibi-character/references/ears-tails-straps.md`，按已解析的依赖目录定位）。在部件表记录承载者、固定/过渡/自由段、刚柔类型、运动方向及接触对象；按专用规则构建和验收，静态与精修模式均检查真实几何连接。

输入含胸卡、扣具、挂包、设备等组合配件时，同时读取底层 [配件构造与连接](../voxel-chibi-character/references/accessories.md)。保留“衣物—短带—扣环—卡套”等连接链、跨部件的多个挂点与实际带尾；不要把配件清单误当已经完成的几何。设计交接沿用 v1，可补充 shapeMode、motionMode、attachments、path、priority，具体转换见 [交接格式](references/sheet/handoff.md)。

## 转换约定

先查看输入四列及底层三维母版的 rig-front/side/three.png，读取 character-baseline.mjs 中实际尺寸，不猜参数。**设定图决定身份、发型组织、服装类别与裁片、配色、配饰与连接；三维银灰狼耳少女母版决定像素几何、基础素体、骨架约定和渲染。**两者都不是任意混合的比例来源。

简化为大体块和有限配色；保留主轮廓、主要辫子/卷发、鞋袜类别与关键配饰。不能用母版红白服装替换角色设计，不能把所有鞋变为同一横带鞋或删掉决定身份的图案。细纹可用少量色块概括，记录省略，不虚称文字可读。建模阶段允许体素阶梯与硬边，设定图阶段的“禁止 voxel”不跨阶段套用。

按 [适配与验收](references/adaptation.md) 将明暗转为角色自身配色：保留衣片内部层次，分别处理头发接界连续与发束对比；虹膜中部保留原色、上下变化克制、高光独立。不把母版的具体色号、眼睛分区数量或表情套给新角色。

若用户要求模型严格继承图片平滑表面/头脸比例，本流程与要求存在冲突；说明并确认实际建模目标，不能宣称体素模型满足严格平滑还原。默认像素任务无需重复询问风格许可。

## 制作流程

1. 在新角色工程保存参考图与设计记录，列出约 5–8 个身份锚点和各部件承载者/刚柔属性。复用已存在角色时先保存可恢复版本；不覆盖唯一母版。
2. 运行底层 skill 的 scaffold.mjs 建立可编辑起点。它仅复制银灰狼耳少女，不识图、不完成新角色。输出目录必须未存在；若 design 已在角色目录下，向其新的 `model/` 子目录 scaffold。不删除目录来强行重跑。
3. 修改 model.mjs、rig-export.mjs、hair-physics.mjs 和 character-spec.json。映射设计交接，保留动态/绑定字段；通用配件的数值尺寸、局部连接点和骨骼绑定写入工程根 spec 的 accessories，由脚手架 build 读取，不能直接复制设计 parts 作为实现。几何组删除或改名同步骨架、权重、运行链和测试 fixture；未知部件报错。
4. 按 [适配与验收](references/adaptation.md) 建立几何、语义颜色和连接关系。先验正侧背轮廓与身份，再调动态。设定图自然站姿用于视觉验收；内部 T-pose 绑定可以保留，两者不冲突，不反向改写设定图为 T-pose。
5. 按上面的动态模式执行：轻量模式默认基础动画 + 2–3 类附加动态，通常 4–8 新骨；完整精修模式逐项评估全部合理活动部件，遵循专用参考，不受该默认数量限制。选择依据来自角色，而非照搬全部 43 骨。只有明确静态请求才省略；无合理活动部件时解释，不把帽冠或鞋做成软体。
6. build 后回读实际 GLB，在真实预览检查外观和运行时动作。通过底层 skill 与本 skill 的相关检查，保存当前角色的结果，不能沿用母版测试报告。
7. 交付可编辑源码、静态/骨骼 GLB、基础片段、动态运行代码、可打开预览、模型实际四视图截图、统计及限制。设定图和模型截图分别命名，禁止用设定图充当建模渲染证明。

## 完成标准

实际导出模型身份与连接正确；骨架和基础动画可播放；所选附加部件在转向/轻推/跑动演示下跟随并回弹；暂停、停止、关闭恢复行为稳定。测试结果对应当前产物。仅复制母版、只交 GLB、有物理文件却未接入、网页未运行或只有数字测试，均不能称完整完成。

GLB 内嵌的 Idle/Rig_Test 与运行时附加动态分别说明；跑动演示不是成品动作库，不承诺其他引擎自动重现弹簧。未完成浏览器/引擎验证时列明范围。默认不增加表情、IK、全布料碰撞、多角色网站或付费服务。
