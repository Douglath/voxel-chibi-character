# 输入适用性与路由

## 先查看，再判断

标准是“能否可靠理解并转换为目标像素角色”，不是要求原图已经像素化、符合固定背景或恰好四列。逐项观察：

- 角色身份是否明确，是否多角色混杂；脸、发型、配色和关键配饰是否可辨。
- 全身覆盖程度：头顶、发尾、衣摆、手脚、鞋袜是否缺失或被裁切。
- 视角、透视与姿势：强缩短、俯仰、动态扭转是否掩盖比例与裁片关系。
- 结构可读性：刘海/后发/辫子、服装层次、袖口、鞋款、附件连接点是否清楚。
- 视图一致性：如果有多个视角，发束、衣服、配饰位置数量、左右关系是否矛盾。
- 对目标的适配难度：能否保留核心身份并合理体素化；精修动态所需的自由末端和挂点是否足够清楚。

不给虚假的成功概率、精确质量评分或“保证效果”。用具体图像证据解释风险。高分辨率不等于结构清楚；只有一张图也不自动判不合格。

## 三条路由

**direct：复用合格四视图。**主要结构清楚、四列身份和连接一致，能支撑目标建模时直接复用，不重复生成。用户明确要求跳过生图时，清楚的单图也可走此路由，记录用户选择及必要推定。

**prepare_sheet：默认先准备四视图。**角色身份可辨，但输入只有原始插画、单视图或尚不合格的多视图时，执行本 skill 的 [内置四视图流程](sheet/pipeline.md)。这也适用于清楚的正面单图，不只在预计效果差时触发。已有合适概念图或仅局部视图错误时按需跳过概念阶段，避免全部重设计。生成内容是设计推定，不能当作恢复了真实背面；保留原图，与原图比身份，与母版比比例。

**needs_input：缺少不可可靠补全的关键信息。**身份看不清、多个目标无法判断、只露局部且关键服装完全未知等。指出缺哪部分，请用户补充清晰参考或描述，不能通过生成图掩盖未知身份。用户明确允许设计缺失部分时，可按该授权进入 prepare_sheet 并标明推定。

用户明确“不要生图、直接建模”时不自动生成；输入清楚则直接继续，有风险则简短说明并按其明确选择执行，记录例外，不反复询问已授权事项。用户要求图中平滑风格严格还原时按主 skill 的风格冲突规则处理，出四视图不能消除体素与平滑目标的差异。

## 缺少能力或未通过检查

检查内置流程、母版资源和当前图像工具。无需独立 chibi-character-sheet；只有文档不代表图像工具可调用。缺失时说明具体问题，例如：“模型 skill 已内置四视图规则，但当前图像生成工具不可用。这张图的后发和袖口被遮挡，直接建模容易误判结构。可以启用图像工具或补充清楚的四视图；也可以明确接受这些推定后继续。”

若内置文件损坏则提示恢复本模型 skill 的资源；不要让用户安装独立出图 skill 来解决工具缺失。不编造安装来源或自动切换付费 API。恢复后从当前阶段继续。

生成失败或生成图仍存在关键矛盾时保留产物和错误信息，停止依赖不合格图的建模，说明具体未解决项。用户明确接受偏差时记录范围再继续；不能把接受风险改写为评审通过。

## 记录与复检

预检结果先保存在角色的 design/input-review.json，后映射到 character-spec.json 的 inputReview：记录输入路径与实际 SHA-256、route（direct / prepare_sheet / needs_input）、具体观察、推定、缺项、所选动态模式、预处理次数与结果。未创建模型工程时也可只建立 design 目录，不需要先复制母版。

预处理返回后记录最终参考路径与哈希，重新检查身份、结构与交接状态；保留原始图与生成图的来源区别。status=needs_revision 不自动放行。精修动态、静态选项和用户限制必须跨阶段保留。只要求预检的任务止于报告，不擅自生成图片或模型。
