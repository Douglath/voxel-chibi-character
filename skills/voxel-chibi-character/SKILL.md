# 体素 Q 版角色

角色参考决定身份、发型、服装裁片、配色与饰件；[银灰狼耳少女母版](assets/silver-wolf-refined-dynamics/) 提供像素几何、基础素体比例、骨架与渲染约定。不要将母版服装、狼耳或配色带入新角色。用户明确纠正优先于生成设定图；像素局部形状、部件整体姿态与动态形变分别处理。四肢执行 [静态肢体转换](references/modeling.md#静态肢体与手部) 和包内 [手部分级标尺](references/hand-thresholds.md)，不直接描摹平滑参考的肌肉曲线或逐根手指。

## 选择交付模式

可在 prompt 中写“模式：快速预览”等名称，也可用自然语言表达目的。名称统一映射到已有的交付与动态字段，不另建平行流程：

| 模式名称 | 配置 | 常见表达与完成点 |
|---|---|---|
| **快速预览** | delivery.mode=preview；动态暂缓 | “先看大致效果/三视图”“最低成本试造型”：真实静态模型和三视图可评审后停止，不自动精修。 |
| **静态成品** | delivery.mode=final；dynamics.mode=static | “完成静态模型，不要动画”：完成约定外观、文件交付与静态验收，不减免成品质量检查。 |
| **轻量动态成品** | delivery.mode=final；dynamics.mode=lightweight | “做成品，带自然的轻微动态”：基础功能和选中附加动态完成，相关验收通过后交付。 |
| **精修动态成品** | delivery.mode=final；dynamics.mode=refined | “精致动态/全面精修动态”：合理活动部件及对应精修验收完成后交付，不扩展为无限细化。 |

明确指定模式时按指定执行；未指定时按本轮目的和已确认范围判断，无变化沿用已有模式，无上下文默认轻量动态成品。仅说“测试”不自动减免验收，“精致外观”不自动升级精修动态。执行前用一句话说明选中模式和本轮交付范围，不为常规模式选择反复确认；明确要求互相冲突且影响交付时才澄清。检查细则统一见 [validation.md](references/validation.md)，动态配置见 [dynamics.md](references/dynamics.md)。

- 快速模式直接复用当前参考或已有模型，不自动另生四视图；不可见处作最少推定，妨碍本轮判断的缺项才询问。已有工程局部迭代，不重做无关部件。先读 modeling 的相关造型部分，暂不加载动态、表情功能及专项测试文档。
- 本轮目标是实际模型的静态三视图，完成 [快速预览范围](references/validation.md#快速预览范围) 后停止，等待用户评审。它是阶段交付，不是永久关闭成品动态；用户要求转成品时恢复正式流程并补齐未验收项。

## 输入与范围

**禁止新增嘴巴：**所有建模模式均采用无嘴脸部；不得新增嘴线、嘴唇、口腔、嘴部几何或贴图，也不得在任何表情或动画中补出嘴巴。参考插画或四视图中存在嘴巴不构成保留依据，建模时仍须省略；只有用户明确要求嘴巴时才可例外。

- 本入口只建模。正式流程默认读取已完成四视图；仅有原始插画时先提示使用独立 `chibi-character-sheet` 出图包。快速模式或用户明确直接按现图建模、禁止出图时可继续，记录必要推定，不因缺少图像工具自行跳过准备。
- 查看真实图像。有完整或简版设计交接时沿用身份、排除项、推定与评审；仅有合格四视图也能自行提取。重大结构矛盾或 needs_revision 先解决，用户已接受的偏差记录范围。由一体化流程调用时复用其输入评审，无变更不重复预检。
- 若目标是严格复制平滑曲面或原图头身比例，先说明与体素母版的冲突并确定目标；普通像素任务不新增风格确认。

**独立过滤道具：**默认只制作角色本体、服装及穿戴饰件，不生成手持物、武器、工具或场景物件；图中存在或属于标志物不构成许可。只有用户明确要求的道具才保留。不得将排除物改挂腰背或为其补造带子、底座、支架；武器工具挂在身上仍属道具，发饰、扣具、身份牌及原有穿戴包袋不一概删除。此规则不依赖出图阶段已清理。

在 character-spec.json 的 scopeReview 中简要记录 kept、excluded、explicitlyRequestedProps 及依据；沿用有效记录，只在范围改变时更新。被排除项不进入几何、绑定、动态或预览，最终按实际 GLB 复核。

## 制作与迭代

1. 开工时查看角色图与母版 rig-front/side/three.png，读取 character-baseline.mjs 的实际尺寸。记录少量身份锚点和部件关系，执行 [造型与绑定](references/modeling.md)。输入及源码保留可恢复版本，不覆盖唯一母版。
2. 新建工程时在未存在的目录运行脚手架；若 design 已占角色目录，使用其新的 model 子目录。已有工程继续局部修改，不删除旧目录重跑。

   ```text
   node <skill>/scripts/scaffold.mjs <new-project> <character-id> <角色名称> <端口>
   ```

   快速模式在命令末尾加 `--preview`，生成静态构建入口及暂缓功能的 spec。已有工程记录 delivery.mode=preview，不覆盖原有动态意图。

   脚手架只复制可编辑母版和 Three.js，不识图、不定制角色。按需修改 model.mjs、rig-export.mjs、hair-physics.mjs 与 character-spec.json；删除/改名部件同步绑定、动态与相关测试。配色后处理适配见 modeling.md，不只改基础色而保留银灰覆盖规则。
3. **先稳定外形。**每批相关修改后只检查改动处、必要视角及基本构建/显示；所用几何与导出路径保持可用。快速模式完成本轮目标与三视图后交付，不自动进入后两步。此时不跑整套动作、多帧率、掉落或碰撞扫描，不反复生成全套截图和报告。
4. **正式流程再适配功能。**默认基础动画与轻量附加动态，明确静态要求才省略；模式与预算见 [动态选择](references/dynamics.md)。复用 [v5 表情与普通眨眼](references/expressions.md)，默认只替换虹膜基色。针对稳定后的改动执行相关专项。
5. **正式交付前集中验收。**按 [检查调度与交付](references/validation.md) 核对最终 GLB 和实际预览；验收后小修只重测受影响项。一次性成品请求自主完成这些阶段，不为阶段切换新增用户确认；外观迭代稿可标待验收，不冒充成品。

`npm run build` 只导出模型，`npm start` 启动预览服务；快速脚手架仅构建静态 GLB，使用 `/character/index.html`，正式流程使用 `/character/rig.html`。构建不等于要求全套测试。正式交付源码、GLB、基础片段、实际运行的表情/附加动态、预览及简短验证结果；GLB 基础动画与运行时弹簧分开说明。

## 固定预览交付

所有生成模型均附带同源的离线游乐场 HTML，读取 [playground.md](references/playground.md)。单模型首次打开进入测试页，可返回游乐场批量导入、浏览与保存；不临时重写一套界面。快速/静态模式仍只创建静态模型，使用同一界面但不为按钮补造骨骼或表情。成品以当前已认可的角色动态效果为准，保留每个角色自己的物理模块、参数及已实现的碰撞约束；不要求统一动态格式，不自动换成通用弹簧。单人和多人使用同一套角色动态，不因进入大厅自动简化。保留专用动态预览作为配套文件。大厅保留醒目的全局物理开关及 FPS、帧时、人数显示；开关只停止附加物理，不停止走动。跨文件导入适配与验收见 playground.md。

行走/跑步的手臂必须按实际绑定姿态校准，肘腕留在躯干各自外侧，左右交替前后摆动；禁止将 A-pose 已下垂角度再次叠加造成交叉内摆。膝盖和手臂方向一起验收，见 [dynamics.md](references/dynamics.md#手臂摆动方向)。

## 控制开销

只读当前任务相关章节、源码段和失败日志；已读且未变内容复用，不每轮重读全部文件。图片和 GLB 使用相应工具查看/解析，不把二进制原始内容当文本读入。批量完成相关小改后再预览；成功只返回短汇总，失败才展开日志，最终版本再集中统计与报告。

优先复用 Node/Three.js 工具并局部适配，不重写渲染器或默认引入付费服务、IK、完整布料碰撞、成品动作库；固定游乐场直接复用随包模板。token 仅报告真实计量，不从耗时或面数估算。
