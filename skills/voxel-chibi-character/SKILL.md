# 体素 Q 版角色

唯一造型、比例、细节及动态参考是 [银灰狼耳少女](assets/silver-wolf-refined-dynamics/)，包含侧发整体化、鬓发分离、覆盖发接界衔接、宽发束及服装内明暗、克制虹膜色阶：3,186 三角面、6,800 顶点、43 骨骼、38 网格、一个顶点色材质、无纹理。旧角色不再作为模板或第二基准。新图决定身份服装，新基准决定表达风格；不要照搬不适用的银灰配色、狼耳、尾巴、黑外套和宽袖。

角色包含兽耳、尾巴或带状附件时，构建前读取 [兽耳、尾巴与绑带](references/ears-tails-straps.md)，按部件类型确定连接、运动方向和专用验收；不能以骨骼挂点稳定替代几何连接检查。

角色含胸卡、扣具、织带、挂包、设备等组合配件时，读取 [配件构造与连接](references/accessories.md)。按可见证据描述部件及连接，再选基础构件；自身是否变形与是否独立摆动分别记录。可选构件包是可编辑起点，不能自动识图或代替角色适配。

头发构建或配色时读取 [头发整体与发束表达](references/hair.md)。完整精修或强扰动验证时读取 [掉落测试](references/drop-testing.md)。新基准是可运行范例；未做完整自碰撞或多角色性能优化，不把当前参数当作通用材质常数。

## 输入与阶段边界

本 skill 只执行建模，不生成参考图。独立使用（包括网页端 ZIP）时，默认接收已完成的角色四视图：先查看实际图像，有 design-handoff.json 则核对最终图、status 和排除项；有重大结构矛盾或 needs_revision 时先解决。仅有原始插画时，说明需要先使用独立 chibi-character-sheet 出图包生成四视图，不因缺少出图工具而悄悄按原图建模。用户明确要求直接按现图建模或禁止出图时才按可见证据继续，并记录背面等最小推定；道具过滤不豁免。

由 character-sheet-to-voxel 调用时沿用其已完成的输入评审，不重复出图。身份信息以最终合格设定图及用户明确纠正为依据，原图仅用于核对，不能把已经剔除的道具重新加回来。

## 独立的道具范围检查

默认只制作角色本体、服装及穿戴饰件，不制作手持道具、武器、工具或独立场景物件。此规则独立于出图步骤：直接读取原图、复用现成设定图、经过四视图预处理时，建模前都重新检查。原图中存在、属于标志物或上游遗漏清理均不是生成许可；只有用户明确要求保留某道具时才生成并记录范围。不得将排除的手持物改为腰挂、背挂或其他随身附件，也不为其补造带子、底座或支架。

发饰、蝴蝶结、服装扣具、身份牌及原有穿戴包袋不一概视作道具；按实际用途分类。武器或工具即使挂在身上仍属于道具，不能以“配饰”“设备”或身份锚点为由绕过过滤。配件构造、连接和动态规则仅适用于确定保留的部件。

建模前在 character-spec.json 的 scopeReview 中记录 kept、excluded、explicitlyRequestedProps 三个清单及简短依据；无道具时清单可为空。上游交接的排除项继续有效，缺少交接字段时独立判断，不假定出图已经兜底。被排除项不得进入几何、配件规格、骨骼、动态或预览；实际模型和导出 GLB 仍须复核。

## 制作

像素几何、部件整体姿态和动态形变分别判断；低面数硬边不自动等于像素风。建模与迭代遵循 [像素表达和服装结构](references/modeling.md#像素表达与部件姿态)，服装叠层按 [验证与交付](references/validation.md#服装层间与闪烁专项) 检查共面及运动间隙。用户对原图的明确纠正优先于生成设定图，不把当前角色的片数、长度、颜色或角度写成通用默认值。

1. 查看用户图与母版 rig-front/side/three.png，提取约 5 个辨识特征。读 [造型与绑定](references/modeling.md)，按部件内部的宽明暗面丰富衣物，不把细节仅理解为新增配件。默认复用已认可 v5 的八表情模板，Normal 带自然眨眼；读取 [表情模板与复用](references/expressions.md)。新角色默认只换虹膜基色，固定眼型、像素排列、眼线和高光；按用户要求选择或修改表情。虹膜保留原基色并克制分层；眼白、眼睛高光与服装使用独立语义配色参数，服装换色不得连带修改眼睛。
2. **新角色默认交付基础动画和简单附加动态，不需要用户另行提出。** 阅读 [动态选择和成本](references/dynamics.md)，选择 2–3 类适合该角色、最影响轮廓的活动部件（如发梢、蝴蝶结垂带、裙摆），通常新增 4–8 骨骼，小领片最后考虑。只有用户明确要求静态模型或禁用动画时才省略；“生成图中的角色”“低开销”“没有额外动态要求”均不能自行解释为静态任务。用户要求完整精修时可参考全部 23 根附加骨骼。角色缺少适合的活动部件时说明原因，不强加不合理的软体效果。
3. 用脚本新建可编辑起点，修改 character/model.mjs、rig-export.mjs、hair-physics.mjs 和 character-spec.json。脚本复制完整银灰狼耳少女，**不会自动识图、定制角色或裁剪动态**。需要通用配件时在工程根 character-spec.json 的 accessories 中填写实现规格，由脚手架 build 读取；设计交接不能直接当作此规格。删除几何须同时调整绑定、动态链、演示和测试。未知部件报错。

   更换角色配色或几何时，按 [配色隔离](references/modeling.md#配色隔离) 同步适配或移除 tonal-colors.mjs、hair-colors.mjs 的母版专用选面规则与派生调色板；只改 model.mjs 的 hair 色仍可能被银灰后处理覆盖。

```powershell
node <skill目录>/scripts/scaffold.mjs <新工程路径> <角色英文标识> <中文名称> <端口>
```

4. 脚手架已携带本工作流所需 Three.js，无需联网安装。`npm run build` 导出，`npm start` 预览。按 [验证与交付](references/validation.md) 查看实际 GLB 及变更相关检查。

默认验收必须看到待机/基础关节动作，以及所选发饰或衣物在转动、轻推或跑动展示中的轻微跟随与回弹。提供可运行预览、角色专用绑定和运行时代码；只有20骨基础动画、仅有未使用的物理文件，或只交付GLB，均不算完成默认附加动态要求。表情模板和眨眼随预览交付；默认不增加 IK、完整布料碰撞或正式动作库。

需要多模型对照、导入或负载测试时，按需读 [多模型与交互验收](references/model-lab.md)，使用可复制的试验室。默认已有单角色动态预览，无需额外交付多模型网站。

## 跨环境使用

本地与网页版共用本 skill，不另维护网页版入口。通过 Google Drive 读取或交付自包含 HTML 时，读取 [跨环境使用与离线打包](references/portable-use.md)。脚手架自动携带所需依赖和 build_html.py；规则、母版、表情、配件与运行时代码均来自同一来源。

## 控制开销

- 程序化 Node/Three.js 优先；默认不调用付费图像/3D 服务，不生成中间图。用户明确选择的方式优先。
- 先轮廓、配色、标志饰品，再动态。母版面数是实证规模，不是必须用完的配额。
- 只读入口、相关参考章节与源码段；复制成熟工具并局部修改，不加载二进制、整份编辑 JSON 或历轮日志，不重写渲染器。
- 性能看面数、顶点、蒙皮骨骼、活动粒子、网格和 draw calls；一个材质不等于一次 draw call。多角色需实测。
- 区分已有面重着色与按颜色重新合面：前者可不改拓扑，后者可能增加色界、顶点和三角面。每次按实际产物记录变化，不把所有配色细化称为零几何成本。
- 记录选中/省略的动态、幅度、原因、统计和限制。token 只报告真实可用计量，区分缓存输入、非缓存输入和输出；不可用就注明，不由耗时或面数估算。
- 保存可恢复版本，新角色不覆盖母版。GLB 包含骨骼和基础片段，实时附加动态依赖运行时代码。
