# 头发整体与发束表达

先区分贴头覆盖发、鬓发、垂落长发和明确外翘的发束。插画中的风吹姿态不等于中性姿态需要侧面凸块。没有依据时不增加耳机状、肩垫状或短厚矩形连接件。

## 结构

- 建模前简记刘海、左右面前鬓发、侧发、后发及独立长束的根部、发流和终点：用眉线、下颌、颈根、肩线等地标表达长度，并记录左右长短、前后遮挡及推定。“短发”不足以限定发尾；左右是否近似等长依参考，不强制对称，也不继承旧模型无依据的长束。先按现有参考及当前交付模式的模型视角核对，再细化分束或动态；缺失视角记录必要推定，不自动补生设定图。改长度时一起调整相关接界。
- 优先少数完整的宽发片。每片能读出根部、延伸方向和末端；阶梯沿发流变化，避免用重复细条、细碎锯齿制造层次。
- 整体化不等于把所有头发焊成一块。参考中鬓发与侧长发明显分开时，保留前短后长、深度错开或局部分界，上端合理接入覆盖发。不要把本范例的两格间隙当成所有角色的规定尺寸。
- 贴头侧发与头顶、后脑自然相接；独立垂发允许分离，但根部要有几何依据。不同运动组保留接触面。
- 连续发片使用连续、兼容的权重。贴头覆盖区和紧邻脸部、缺少活动间隙的上段可稳定跟随头部，只让有空间的自由发梢响应；不为了整片都动而扩大穿脸风险。合并后检查原骨链是否把它拉成帘子；外观合并不等于减少模拟成本。

## 侧发体积与贴脸厚度

分别建模并记录面前鬓角、外层侧发、侧后覆盖发，不能用单个统一厚度参数控制整头。参考或用户要求“侧发饱满、贴脸部分薄”时同时满足：

- 面前鬓角：薄片略离脸面，发尾按参考内收包脸；避免用深厚长方体增加存在感。
- 外层侧发：从发根过渡到主体发量，再向末端收束。参考有外张时，记录外张最宽点的高度与末端收拢位置；不能只把整个发片平移或等比加粗。
- 侧后覆盖发：头顶、太阳穴、后脑与发尾有连续体积过渡；侧视检查前后深度变化，斜视检查与鬓角的层次。不能用一块从顶到底的等厚平板，也不能只加宽正面轮廓假装增加侧面体积。
- 层次：用少数宽发束的前后错位、宽度变化和错开的末端表达，色阶只是辅助。避免重复竖条、密集槽沟或无依据的大侧凸块。

**局部减薄不等于减少整体发量。**削薄刘海或鬓角时保留外层侧发已认可的宽度、最宽位置、后脑深度和发尾轮廓；若确需改变这些，记录关联原因。修侧发饱满度时也不自动加厚贴脸发片。

把相关部件的截面控制点保存在工程中；正面比较包脸与露眼范围，侧面比较厚度/后脑过渡，斜视比较内外层分离。临时同色材质下仍应能读出体积。检查真实导出模型，着色和正面截图通过不代表结构通过。

这些是按参考表达体积的方法，不要求所有发型中段外鼓、发梢内卷或使用同样尺寸。示例页展示“薄鬓角与饱满外侧发并存”，不是本角色外观验收或新母版。

## 配色

- 先保证轮廓，再用克制但可读的宽亮暗面表达少量发束。避免等宽、等距、贯穿全长的亮色细条；亮暗面可错开起止高度，少量阶梯转折沿发流延伸。低对比不等于把已成立的分束层次压成单一平面。
- 后发过平时，可先试两三组同色系亮暗面；只有色阶不足以表达结构时再加少量厚度变化。不要默认同时加凹凸和强对比。
- 分开处理两类问题：头顶覆盖发与刘海、侧发、后发相接处的颜色衔接，以及各发片内部的发束对比。参考为连续同色头发时，先修接界的突兀断色，内部保留可读的宽明暗面；不能为消除接缝而统一压平整头颜色。参考明确的挑染或双色分界照常保留。
- 鬓发与侧发不强制不同颜色。当前基准保留鬓发原色，用前短后长、深度错开和轮廓区分；独立提亮鬓发的已撤回尝试不作为默认。后发/侧后发的层次可保留足够辨束的对比，不将具体银灰色号或对比强度强套所有角色。
- 保持语义配色隔离。色阶不需要新增材质，但体素合面可能因色界变多，必须重新统计面数；不声称换色永远零几何成本。

## 检查

按 [validation.md](validation.md) 当前模式选用视角与动作。看实际导出的正面、侧面、背面、斜视；根部或厚度关系不清时补充顶视。分别检查头顶到前/侧/后发的接界连续性、发片内部层次，以及鬓发与长侧发的几何区分，不以其中一项通过替代另外两项。必要时临时统一头发颜色辨认轮廓，不要求每个预览永久增加按钮。检查是否有无依据凸块、悬浮根部、开洞、块状装饰，以及跑动时多条独立摆动形成的帘子感。观察头发与脸、肩、衣领的接触。局部修订保留已认可层次与可恢复版本；用户回退的尝试不能写成默认规范。

## 可复用构造与风格对照

先读 [局部迭代](part-iteration.md)，再按本角色参考选构造。随包 [三种构造对照](../assets/hair-kit/example.html) 是可旋转的技术样例：左为直条反例，中为体素阶梯，右为硬边平面。它不是新的角色母版或审美通过样本；不要复制其配色、三缕刘海或比例到所有角色。通过本地 HTTP 服务打开，禁止将其替代正式模型游乐场。

[lock-geometry.mjs](../assets/hair-kit/lock-geometry.mjs) 接受根到梢的截面数组，每段为 `{x,y,z,width,depth}`，局部 Y 严格递减、+Z 朝脸。根据地标放少量截面：根部、外张位置、内收位置、梢部；不要用大量点拟合平滑曲线。宽度和深度独立控制，修薄刘海优先减 depth，不顺带缩短轮廓或压扁整头。

- `voxelizeLock(sections, step)` 返回整数网格占用 `[ix,iy,iz]`，默认体素风格使用此路径；传给工程现有网格生成器，step 取当前角色格距。低于一格的细梢会扩大到一格，必须实际检查。过陡斜率和细宽可能产生断点；当前 helper 不保证任意输入连通，发现断点应调整截面/格距，不能默默桥接改变造型。
- `createLockGeometry(THREE, sections)` 返回封闭硬边 BufferGeometry，仅在参考与既定风格允许少量斜面时用。保留平面法线，不调用平滑法线焊接。每段独立封顶，避免不同运动组之间剔掉支持面。
- `mirrorSections(sections)` 只提供镜像起点，左右异形必须分别调整。三种函数不判断脸部碰撞，也不自动补头壳、绑定或生成物理。
- `lockAlong` 是按截面序号归一化的根梢属性，供工程自行生成权重；不是物理结果或等弧长距离。贴脸根段保持稳定，按实际活动空间设自由端权重，不能把全段绑定一个摆动骨骼后声称完成精修动态。

参考调用：

```js
import {voxelizeLock} from './lock-geometry.mjs';
const cells = voxelizeLock(part.sections, characterGridStep);
// 将 cells 加入该语义部件自己的占用集合，再走现有 mesher/绑定/导出。
```

局部检查顺序：正面轮廓与层次 → 侧/斜视厚度和遮脸范围 → 发根对头壳的覆盖 → 本轮涉及的活动端。脸的表面、覆盖发底面与独立活动刘海分别保留；用减薄发片修体积问题时不得同时挖空底层。辅助测试 `node assets/hair-kit/test-lock.mjs` 仅证明样例封闭、法线朝向与体素连通，不能代替实际角色 GLB 检查。
