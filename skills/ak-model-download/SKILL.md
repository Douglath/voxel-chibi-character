# 明日方舟模型下载

读取用户指定的 `batch-handoff.json`，使用其中已有会话 URL 回收网页实际交付。默认检查一轮；仍在生成的记录待下载。用户指定试跑时只处理试跑范围。

如本技能目录存在 `settings.local.json`，读取其中本机路径/链接作为默认值；用户本轮明确指定优先。配置不随发布包分发，安装或升级时保留。未配置时从当前项目上下文定位，无法确定所需路径再询问；README 列出字段和外部依赖。

## 固定保存位置

本机统一根目录：`<当前用户 Downloads>/Arknights-Models`。

后续所有模型保存为 `Arknights-Models/<job_id>/<角色名或slug>/`，保留网页原文件名。用户另指定目录时使用其指定位置。

浏览器能指定下载位置时直接保存到对应子目录；只能下载到系统 Downloads 时，将本次实际下载完成的文件整理到对应子目录。只处理已确认属于当前任务的文件。同名相同内容复用，同名不同内容另存，保留原件。

旧交接中的 `download.return_dir` 是历史位置，不能覆盖新的统一根目录。已下载的历史文件不自动迁移；新下载使用上述目录。记录新文件的绝对路径，不把 Downloads 外部路径塞入只接受工作区相对路径的旧校验器。

## 下载流程

1. 读取批次、角色与原会话对应关系，复用已下载文件；不重新筛选、不生成设定图、不重新发送建模任务。
2. 打开原会话，下载已完成回复实际提供的工程 ZIP、GLB、HTML 及其他交付。接受实际文件名，不要求固定七文件、manifest、skill 指纹或输入哈希核对。
3. 以真实文件落盘为下载成功依据，记录文件名、大小及会话地址。ZIP 可做可读性检查，不开展建模、运行时或视觉验收。
4. HTML 等文件已完整包含在工程 ZIP 时，下载 ZIP 即保留了这些交付；不必为了独立附件反复操作或补发消息。用户要求提取时原样提取，注明 ZIP 来源。
5. 每个角色目录保存 `download-record.json`，记录角色、会话 URL、实际文件路径、下载时间与状态。根目录保存或更新 `download-index.json` 以便续传；原批次仅更新下载进度和外部目录指针，保留历史记录。不要把“下载完成”写成“模型验收通过”。
6. 尚在运行、缺少附件或链接失效的如实记录后继续其他项目。默认一轮结束，不无限等待；用户要求持续回收时才继续低频检查。

## 范围

本 skill 仅下载和整理下载文件。不自动导入 catalog、复制到 Playground、修改门户配置、关联立绘管理界面或标记“已建模”。这些操作只有用户另行明确要求时才作为独立任务执行。

最终简短报告下载数量、待下载项和统一文件夹路径。
